# 零碳园区 UI Skill

## 用途
当用户要求生成、修改、扩展零碳园区管理平台的页面、组件、原型或交互时，使用本 Skill。

## 必读顺序
1. `references/零碳园区_UI规范.md`
2. `assets/零碳园区_UI组件库.html`

## 规则优先级
1. UI 规范中的硬约束 / 【必须】条款
2. 组件库已有实现
3. 用户当前业务需求
4. 通用设计经验

若发生冲突，必须按以上优先级处理。

## 生成原则
- 优先复用组件库已有组件，不重复造轮子。
- 不得擅自修改 Design Token、字号、颜色、间距、表格高度、菜单逻辑。
- 新组件必须继承现有 Token 和交互规范。
- 左侧导航、hash 路由、表格、分页、弹窗、抽屉、Toast 等必须遵守 UI 规范。
- 生成前必须执行“组件语义检查”：先判断用户意图，再选择 Form Modal / Detail Modal / Confirm Modal / Drawer / Toast，禁止只按外观套组件。
- 每个操作区最多 1 个主按钮；删除/停用等破坏性操作必须使用自定义 Confirm Modal。
- 禁止僵尸交互：分页、开关、弹窗按钮、表格行操作必须有真实行为或明确占位反馈。
- 演示姓名统一使用：张三、李四、王五、赵六、孙七。
- 不使用真实人员姓名。
- 默认输出为可直接打开的单文件 HTML；如用户要求拆分页面，则按页面拆分，但仍保持同一套组件与规范。

## 关键硬约束摘要
- body 基准字号：12px
- 顶栏：56px
- 左侧菜单：172px
- 内容区 padding：12px 18px 20px
- 卡片圆角：8px
- 控件高度：30px
- 主色：#1D5BFF
- 表头高度：31px
- 数据行高度：36px
- 表格：`table-layout: fixed` + `<colgroup>`
- 菜单折叠：必须用 `max-height` 过渡
- 子页路由：必须使用 URL hash
- 禁止额外叠加一套主 Tabs 导航
- Form Modal：440px，复杂表单 640px；Detail Modal 单一关闭按钮
- Drawer：560px，长详情/复杂配置使用
- 删除/停用：Confirm Modal + 危险实心确认按钮
- 同一操作区最多 1 个主按钮；异步提交使用 Loading 防重复

## 修改页面时
1. 先读取 UI 规范。
2. 再检查组件库是否已有对应组件。
3. 能复用就复用。
4. 不足时按规范新增组件。
5. 仅修改与需求有关的部分，避免破坏公共组件。
