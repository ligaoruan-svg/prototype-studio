# 架构第一步测试（用自己的模型跑）

## 开始前

1. 关掉原型工坊，双击 `scripts/启动原型工坊.command` 重新打开（后台改过，旧的服务不认新功能）。
2. 浏览器里按 ⌘⇧R 强制刷新一次。
3. 每道题新建一个空项目（不导入原型），点顶上「架构」打开画布，对话会自动切到「架构」模式。

## 三道题（整段复制粘贴进对话发送）

### 题一：物业报修

```
物业报修管理后台（电脑端）
业主在小程序提交报修（分类、描述、照片、预约上门时间）
客服在后台受理、派单给维修工，紧急报修 30 分钟内必须派单
维修工在后台接单、上门、填写处理结果和用料，完工后业主评价
维修产生的材料费、人工费要记录，月底和收费系统对账（收费系统已有）
主管要看工单统计、超时工单、维修工绩效
```

### 题二：零碳园区

```
零碳园区能碳管理平台
接入园区电表、光伏、储能数据（来自能源采集系统，已有）
按区域、楼栋、企业看用电和碳排放，按月核算碳排放（范围一、范围二）
设备运行监测和告警，告警要能派单处理、跟踪到关闭
减排措施登记，跟踪进度和减碳量
园区管理员、能源专员、企业用户三类角色，企业用户只能看自己的数据
```

### 题三：商业招商

```
商业综合体招商与租户管理系统
招商线索从意向、洽谈、缴意向金锁定铺位、签约到落位
一个铺位同一时间只能被一个品牌锁定或签约，意向金锁定 15 天到期自动释放
合同起始日不能早于意向金缴纳日，免租期要自动推算正式起租日
租户入驻后管理证照，证照过期要提醒并暂停出账单
退租后铺位自动释放为空置
```

## 每道题按顺序做五件事，对照着看

| # | 做什么 | 看什么（对的样子） |
|---|---|---|
| 1 | 粘贴需求发送 | 先出「业务梳理」卡片，画布不动。角色对、业务对象全、状态流转合理（谁让它从哪到哪）、规则具体能验证、外部系统（小程序、收费系统、采集系统）放进了「不做 / 外部」、问的问题不超过 3 个且问在点子上 |
| 2 | 卡片底部写一句修改发送，比如「费用这次不做」 | 出新版梳理，旧卡显示「已更新」，只改了你说的地方 |
| 3 | 点问题的选项，再点「按这个画架构」 | 画出页面树：模块按业务分（3–7 个）；每个业务对象有列表、详情、新增；流转动作都有按钮且写了「出现：」「确认后：」；表格名字具体（不叫「列表」）；回复最后有一句「检查：…」 |
| 4 | 说一个小改，比如「工单列表加一个转单按钮」或「把维修工管理改名为维修团队」 | 回复很快、很短；画布上只变了说的那处，别的卡片没动；改名的卡片还是原来那张（没有变成删了再加） |
| 5 | 问一句「这个架构合理吗？」 | 只回答，画布不动；有建议会列成「可以这样改」，点了才改 |
