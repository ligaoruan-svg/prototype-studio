# 原型工坊 v5.2 技术说明

## 目标

把「导入现有原型 → 交互预览 → 点选 / 拉框 → 说清怎么改 → 精确修改 → 校验 → 新版本」做成一个闭环，
全部在本机运行，模型接口由用户自己配置。

## 关键决策

1. 工作台与业务原型彻底分离：原型运行在 iframe 里，注入 Bridge 通过 `postMessage` 通信，不直接操作 iframe 内部。
2. 模型不重新生成整份 HTML，只调用局部补丁工具；大页面不会因输出上限被截断。
3. 定位依赖原始源码偏移，BeautifulSoup 只用于查询，替换按字节区间进行，未涉及区域保持原样。
4. 两阶段提交：候选 → 结构 / 脚本语法 / 启动检查 → 落盘并生成版本；失败退回上一版。
5. 区域标记（`#region`）必须独占一行才被识别，页面正文或脚本里出现同样字样不会干扰解析。

## Agent 工具

| 工具 | 作用 |
|---|---|
| `inspect_page` | 页面摘要、标注目标、区域骨架 |
| `search_source` | 关键词搜索并返回上下文 |
| `read_source_slice` | 按行读取源码片段 |
| `read_region` | 读取一个区域的原始代码，作为精确补丁依据 |
| `apply_operations` | 执行局部补丁 |
| `verify_page` | 校验结构与断言 |
| `report_result` | 结束前汇报结论和每条修改意见的结果 |
| `ask_user` | 歧义较大时提一个带 2–3 个选项的问题，不修改 |
| `answer_user` | 只讨论模式下回答并给出最多 3 条待确认建议 |

补丁操作：set_text / set_html、set_attr / remove_attr、add_class / remove_class、
insert_before / insert_after、replace_outer_html / remove、append_style / append_script、
replace_source_text、replace_region、set_token、set_style。

`replace_region` 需要先读过该区域，且精确补丁至少失败过一次才允许，避免整块覆盖成为首选。

## 稳定性约束

- 模型 `finish_reason` 为 `length` 时立即中止并提示「改动太大」，不会应用半截修改。
- 工具参数不是合法 JSON 时明确报错，不会被当成空参数执行；连续三次无效即终止。
- 程序自身异常写入日志并归类为「内部错误」，不伪装成补丁失败让模型盲目重试。
- 工具循环上下文超过预算时，较早的读取结果自动收起为一行摘要，保留调用配对。
- 手动写样式的选择器走白名单（`data-pid` / `id` / `class` / 标签 / `:nth-of-type` 的简单组合）。
- 主预览与后台检查用完全相同的 iframe sandbox 权限。

## 状态与撤销

- 状态流：待发送 → 读取 / 定位 / 修改 → 待确认（检查中，禁止新的写操作）→ 已保存。
- AI 修改、手动微调、版本退回合并为一条撤销时间线，只能从最近一步开始撤。
- 撤销本身也记录为一次修改，历史版本不会被覆盖。
- 只有模型明确汇报为 `completed` 的修改意见才会被消费，其余继续留在画布上。

## 错误分类

后端返回结构化错误码，前端据此给出对应的下一步按钮：
`output_limit`（缩小范围重试）、`patch_target`（重新点选后重试）、`validation`（让 AI 修复 / 放弃）、
`model_account`（打开设置）、`network`（重试）、`internal`、`invalid_arguments`、`iterations`、`conflict`。

## 提示词

系统提示词放在 `prompts/`，与代码分离，可直接编辑：
`agent-system.md`（修改模式）、`discussion-system.md`（只讨论模式）、`design-spec.md`（设计规范，可换成公司规范）。
