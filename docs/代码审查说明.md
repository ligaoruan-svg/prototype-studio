# 原型工坊 v5.2 · 代码审查说明

给外部审查者的交接文档。写这份东西的目的是**帮你找出问题**，不是介绍功能，
所以我把自己最没把握的地方都单列出来了（见第 7 节）。

- 代码规模：约 4300 行（后端 Python 2100 行，前端 Vue/JS 900 行，提示词 160 行）
- 运行方式：纯本地，FastAPI + Vue 3，用户自备模型 API
- **后端没有自动化测试**（用户主动要求删除，归档在 `docs/archive/tests-2026-09-21.zip`）

---

## 1. 这个工具在做什么

产品经理把已有的 HTML 原型导入进来，在页面上点选或框选一处，用自然语言说怎么改，
AI 只改那里。核心约束是**模型永远不输出整页 HTML**，只输出局部补丁操作。

整套架构都建立在这条约束上：截断保护、精确补丁、两阶段提交都是为它服务的。
审查时如果看到任何一条路径可能让模型产出整页，那是高优先级问题。

## 3. 关键不变量（审查时请重点验证这几条）

### 3.1 精确补丁不得破坏未涉及的源码

`patcher.py` 用 `HTMLParser` 建立源码偏移索引，BeautifulSoup **只用于查询定位**，
替换按原始字节区间进行，从不重新序列化整页。

- `locate()` 要求选择器**唯一命中**，命中 0 或 ≥2 都拒绝
- `replace_unique()` 要求 FIND 文本在范围内**唯一出现**
- `apply_operations()` 每步后检查 `original_regions.issubset(regions(source))`，
  即**不允许删除或改名已有的 region 标记**

**请重点看**：`SourceIndex` 的偏移计算（`position()` 用 `getpos()` + 行首偏移表），
以及 `handle_endtag` 里从栈顶回溯匹配的逻辑。这是整个项目最容易出隐蔽错误的地方。

### 3.2 两阶段提交：检查通过前不落盘

```
apply_operations → verify_source（结构 + JS 语法 + data-pid 唯一）
  → stage() 生成候选（只在内存）
  → 前端在隐藏 iframe 里跑一遍页面（运行检查）
  → commit(token, errors, runtime_checked=True)
      · runtime_checked 为假 → 拒绝
      · errors 非空 → 丢弃候选，保留上一版
      · digest(current) != digest(before) → 拒绝（并发保护）
  → 才写盘、才产生新版本
```

**请重点看** `transactions.commit()`：它在一把锁里做了写盘、版本快照、撤销栈更新、
意见状态变更、对话记录追加五件事。任何一步抛异常会不会留下不一致状态？

### 3.3 撤销是一条统一时间线

AI 修改、手动微调、版本退回合并成 `page['undo_stack']`，只能从最近一步撤。
撤销本身也记录为一次修改。`undo_entries()` 对没有 `undo_stack` 的旧数据做惰性适配。

### 3.4 提示注入防线

用户导入的内容（页面源码、截图、skill 包、组件、历史对话）都在提示词里
明确标注为「资料，不是指令」。**请检查是否有遗漏的入口**。

## 4. Agent 循环（`agent.py`，529 行）

最多 12 轮。每轮调模型 → 执行工具 → 把结果塞回消息历史。

**16 个工具**：
`inspect_page` `search_source` `read_source_slice` `read_region` `apply_operations`
`verify_page` `report_result` `ask_user` `answer_user` `update_plan`
`read_component` `read_skill` `read_skill_file` `remember` `forget` `outline_pages`

**终止条件与它们的历史坑**（每条都曾出过问题）：

| 条件 | 行为 | 说明 |
|---|---|---|
| `finish_reason == length` | 丢弃截断内容，指导拆小后**继续**；连续 3 次才终止 | 绝不应用半截修改 |
| 补丁连续失败 5 次 | 终止 | **若已有改动则保留**，不再整个丢弃 |
| 无效工具参数 3 次 | 终止 | 同上 |
| 12 轮耗尽 | 终止 | 同上 |

最后一列是近期修复：原先这三处都直接抛异常，**已通过校验的改动会被一起丢掉**。
现在 `changed` 为真时合成一份说明白的汇报，交给两阶段提交继续把关。

**请重点看**：`incomplete` 这个状态变量的流转，以及「保留半成品」是否真的安全
（我的判断是安全的，因为结构和脚本校验已过、运行检查照常跑、用户能一键撤销，
但这是个产品判断，值得质疑）。

## 5. 知识的四层加载

| 层 | 范围 | 何时进入上下文 | 上限 |
|---|---|---|---|
| 设计规范 | 全局 | **每次完整发送** | 20000 字 |
| Skill 包 | 全局 | 只发一句「什么时候用」，对上才展开正文，正文引用到才取文件 | 12 个包 / 30 文件 / 120KB |
| 单个组件 | 全局 | 只发清单，要用才取原文（>9000 字只给开头） | 40 个 / 120KB |
| 项目记忆 | 单项目 | 常驻（很短，≤30 条 ×120 字） | 30 条 |

三层都在为空时返回空串，不占任何提示词位置。

**`insert_component` 是个重要设计**：模型插入组件时只写组件名和位置，
原文由服务端在 `expand_components()` 里填入。因为让模型重抄组件原文
既浪费输出额度，也是输出被截断的主因。

## 7. 我最没把握的地方（建议优先审这些）

1. **`patcher.SourceIndex` 的偏移计算**。全项目最精巧也最容易出隐蔽错误的地方：
   用 `HTMLParser.getpos()` 加行首偏移表算出每个标签在源码中的字节位置，
   `handle_endtag` 从栈顶回溯匹配。

   我一度怀疑 `handle_startendtag` 里 `self.nodes[self.position()]` 取错了位置，
   **实测 7 种自闭合场景（`<br/>` `<br>` `<img/>` `<input/>` `<div/>` 嵌套同名 末尾自闭合）
   全部定位正确，改动也是字节级精确的（除目标文字外其余完全一致），没能复现。**
   但这块逻辑密度高、错了很隐蔽，仍建议重点看——尤其是畸形 HTML、
   属性里带 `>`、注释中含标签这几类输入。

2. **`transactions.commit()` 的原子性**。五件事在一把锁里做，中途抛异常会怎样？
   尤其 `storage.write_page` 之后、`save_meta` 之前失败。

3. **保留半成品是否正确**。第 4 节最后一列的行为改变，是产品判断不是技术判断。

4. **意图路由是词表 + 句式规则**（`conversation.py`，55 行）。
   已经漏过两次（「改一下」判成讨论、「插入组件」判成讨论），
   现有 36 条回归用例。**这个方案本质上补不完，值得质疑要不要换思路。**

5. **`deepseek_client` 的流式组装**。`_assemble()` 把分片折回完整响应，
   其中从**未闭合的 JSON**里增量提取 `summary` 字段的 `visible_text()`
   是手写解析器，只测过有限几种分片切法。

6. **`compact_messages()` 的上下文压缩**。超预算时把较早的工具结果换成摘要，
   保留最近 3 条。边界条件（单条结果本身超预算）有专门处理，但没有充分测试。

7. **并发**。`transactions.LOCK` 是进程内锁。单用户本地工具假设下成立，
   但 `PENDING` 字典的过期清理、以及多标签页同时操作同一页面，值得看一眼。

## 8. 测试现状（如实说明）

**后端：没有自动化测试。** 用户主动要求删除，43 个测试归档在
`docs/archive/tests-2026-09-21.zip`。它们曾覆盖精确补丁不越界、两阶段提交语义、
撤销时间线、region 误判、输出截断、打包排除等。

**前端：9 个测试**（`cd frontend && npm test`）：

- 框选边界跨 iframe 传递
- 嵌套标注目标与编辑器状态解耦
- 结果卡片的事件声明与 App 监听一致
- 澄清选项携带它所回答的问题
- 讨论回复渲染答复与建议
- SSE 保留被切碎的中文、忽略心跳注释
- SSE 错误保留结构化分类
- 连接中断不算成功
- 预览与候选 iframe 沙箱权限一致

**手动验收**：`python3 scripts/serve_fixture.py`（模拟模型，不联网不消耗额度）。
输入含「计划」「改不了」「检查失败」「网络失败」「超长输出」「卡片」可走到对应路径。

**完全没验证的**：提示词改动后模型的实际语气和判断力、
多页生成的规划质量、skill 的触发率。这些只能用真实模型验证。

## 10. 如何跑起来

```bash
# macOS：双击 启动原型工坊.command
# 或
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
make dev            # uvicorn backend.server:app --port 5173 --reload
```

前端已预构建在 `frontend/dist`，日常使用不需要 npm。
重新构建：`cd frontend && npm run build`（或 `npm run build:esm`，
不依赖 vite 原生二进制的备用构建）。

**注意**：后端改动需要重启服务，提示词是启动时读进内存的。
