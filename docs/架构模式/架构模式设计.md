# 架构模式设计

## 现在的做法（第五版）：一块画布 + 对话里的「架构」模式

平时不用架构；点顶上的「架构」才打开，和对话里的「架构」模式绑在一起：

- **画布**：中间只剩一块画布，上面是这个原型的页面树。可以手动加模块、菜单页、页签、弹窗、按钮，改名、挪、删；选中卡片时右边出详情，改字段和控件。右上角只浮着撤销和关闭。
- **导入过原型的**：打开时从原型读（和「展开」一样把每页点一遍），**只合并不冲掉**：
  - 原型里新做出来的补进画布。
  - 画布上规划了、原型里还没有的留着，卡片是虚线，标「原型里还没有」，带一个「让 AI 做出来」：把话填进输入框、切到「自动」，看一眼再发。
  - 原型里已经删掉的也留着，卡片淡掉，标「原型里已经没有」，删不删你决定。
- **没有原型的**：画布是空的，自己加，或者在「架构」模式里跟 AI 说。
- **对话的「架构」模式**：画布打开时自动切过去，关掉回到原来的模式。这个模式里 AI 只改画布上的页面树（写大纲，不写代码，几秒），改到的卡片亮一下，能撤销。
- **切回「自动」「直接改」**：画布开着时，AI 拿整张画布当背景做页面（规划中的标着「原型里还没有」）。
- **同步到原型**：画布上加的、删的、改名的、挪的、改了字段 / 按钮的，右下角记着「N 处没同步」（改过的卡片右上角一个小点），点开看清单。点「同步到原型」把这几处写成一段话填进输入框、切到「自动」，看一眼再发。
  - 后台记着上一次从原型读出来的样子（`architecture.base.json`，编号和画布对得上）。画布和它比，多做的就是没同步的改动。只写在画布上的介绍、谁用这些不算。
  - 再从原型读时，新读的树按名字对上旧编号（画布上改过名的也认），再把没同步的改动重放上去：删掉的不会被补回来，改名的不会变成两个。AI 照着改好了，那一条自然就没了。
- **砍掉的**：数据关系、业务流程、统一规则、一致性检查、AI 起草、按架构整份生成、用文字编辑、粘贴功能清单、画布上方的搜索和层级。

代码：`backend/arch_expand.py`（展开图 → 页面树、合并）、`backend/arch_chat.py`（架构模式的对话）、`backend/architecture.py`、`frontend/src/composables/useArchitecture.js`、`frontend/src/components/architecture/`。

## 三个视图

### ① 页面树

- 层级：系统 → 模块 → 菜单页 → 页签 / 下钻页 → 弹窗、抽屉、跳转、区块 → 功能。
- 每个节点要写清楚：
  - 一句话介绍、谁用
  - 怎么进来：菜单、隐藏直达地址、从哪个按钮跳过来、带什么参数
  - 怎么返回，返回后菜单高亮哪一项
  - 用到的数据、复用的区块、需求编号
- 可以添加、删除、改名、拖动排序、收起；删除可以撤销。删除前提示影响范围，比如「这个巡检点被 2 条路线用到」。

### ② 数据关系

- 所有页面共用**一份**示例数据。
- 节点是实体：编号、字段、状态流转。
- 连线是引用关系：1→N、有序 N:N、模板→实例。
- 字段用符号标记：🔑 编号、↗ 引用、ƒ 自动算、🔒 继承不能改、⚠ 对不上。
- 外部系统用虚线框，数据只读。

### ③ 业务流程

- 按泳道排：管理员（电脑）/ 系统自动 / 不做的端（虚线）/ 外部系统（虚线）。
- 不做的端和外部系统不生成页面，只生成它们产生的数据，保证下游页面有数据可看。

## 电脑端统一规则

生成每一页都按这套规则，避免各页各做各的。

| 场景 | 规则 |
|---|---|
| 列表页 | 页头 → 筛选区（查询 / 重置）→ 操作栏（左边新增、右边导出）→ 表格 → 分页 |
| 查看 | 右侧抽屉，只读 |
| 新增 / 编辑 | 居中弹窗。和查看共用同一套表单，查看时只读 |
| 多步操作 | 向导弹窗，带步骤条 |
| 跳转 | 带编号打开对应的抽屉，或切到对应页签；关掉后回到原列表 |
| 行操作 | 按状态出现，例如离线才显示停用、待执行才显示开始 |
| 页签 | 一个菜单下的多个页签共用菜单入口，每个页签可以单独直达 |
| 外部数据 | 标明「由 XX 系统回传，只读」 |
| 数据 | 全局一份；引用必须存在；派生值（个数、进度、摘要）由数据算出来，不能写死 |

## 本次范围

- 只做电脑端。涉及手机执行的按钮（例如「开始巡检」）保留，点击只给提示。
- 手机执行产生的数据，例如打卡记录，用示例数据代替。

## 生成规则

1. 按数据依赖排生成顺序，例如：设备定义 → 设备录入 → 巡检点 → 路线 → 计划 → 任务 → 记录 → 异常跟踪 → 统计。
2. 一页一步生成。只有改过的节点需要重做。
3. 生成完成后跑一致性检查：
   - 引用的数据是否存在
   - 派生值是否和数据一致
   - 区域等字段是否前后对得上

## 第一版做了什么

- 顶栏多了「架构」：没有架构时可以「AI 起草架构」（写几句需求）、「从当前原型整理」、「空白开始」。
- 三个视图：
  - 页面树：选中卡片后出现工具条，可以加子项（按父节点给可选类型）、加同级、上移下移、删除；删除后底部能撤销。
  - 数据关系：按依赖分列，自动画引用连线。
  - 业务流程：按泳道排，箭头从左往右。
- 右侧详情：可以改介绍、入口、地址、参数、返回、用到的数据、标签、需求编号；数据的字段、引用、关系；流程的泳道、下一步、对应页面。
- 一致性检查：数据不存在、引用断了、流程指向不存在的步骤都算错误，没改好不让生成；缺介绍、没被用到的数据算提醒。
- 「确认架构，按架构生成」：
  - 状态改成已确认，回到预览，把架构（页面树、数据、流程、统一规则、生成顺序）放进 AI 背景，一页一步做。
  - 每做完一步重开对话时，架构也会带上。
  - 轮次上限按页数放宽。
- 单个页面可以「只重做这一页」。
- 电脑端统一规则：写进了系统提示（新做页面时用；已有原型有自己的写法时跟原型走），也可以在架构里改。

## 还没做

- 生成后自动对照架构检查（页面上是不是真有这些页签、弹窗，数据是不是对得上）。
- 拖动排序、整棵树导出成图片。
- 手机端。

## 拆到弹什么（第三版）

- 页面树只管到页面这一层：模块 → 菜单页 → 页签 / 下钻页。
- 新增「页面结构」视图：一次只看一页，按页面从上到下排开。
  - 区块、表格（列）、按钮，以及按钮打开的弹窗 / 抽屉（字段、确认后数据怎么变）。
- 按钮写清点了以后怎样：打开 / 跳到 / 执行 / 二次确认，还有「什么时候出现」。
  - 点「打开「xx」」直接跳到那个弹窗。
  - 打开的东西在架构里找不到，一致性检查会提醒。
- 新类型：表格、按钮。
  - 弹窗、抽屉、向导、区块可以写字段（必填加 *）。
  - 弹窗写「确认后」。
- 大纲写法：

  ```
  新增模板 [按钮] | 打开：新增核算模板 | 出现：有权限时
  新增核算模板 [弹窗] | 字段：模板名称*、行业 | 确认后：列表多一行
  列表 [表格] | 列：模板编号、状态
  ```

- 照展开图整理会自动拆到这一层：
  - 筛选项、表格列。
  - 每个按钮打开了哪个弹窗或子页面、弹窗里的表单项。
  - 表格行里的按钮挂在表格下面。
