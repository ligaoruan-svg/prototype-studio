# 原型工坊 · 架构说明

给以后改代码的人（包括 AI）看的地图：东西在哪、怎么串起来、哪里该先动。用户向的说明在根目录 README。

## 一张图

```text
浏览器 / 桌面窗口（Vue 3）                       本机服务（FastAPI，backend/）
┌──────────────────────────────┐   HTTP + SSE   ┌──────────────────────────────────────┐
│ App.vue：状态中枢，provide 给  │ ─────────────▶ │ server.py：全部接口                   │
│   layout / chat / expand /    │                │  ├ agent.py：AI 循环（工具调用）       │
│   settings 各组件             │ ◀───────────── │  ├ patcher.py：精确补丁 + 静态检查     │
│ 预览 iframe（sandbox）        │   执行进度事件  │  ├ transactions.py：候选 → 检查 → 落盘 │
│   └ bridge 脚本：点选、检查、 │                │  ├ storage.py：项目 / 版本 / 回收站    │
│     自检，postMessage 回报    │                │  ├ memory.py：项目记忆 / 个人习惯      │
└──────────────────────────────┘                │  └ deepseek_client.py：调模型接口      │
                                                 └──────────────────────────────────────┘
```

## 一次「AI 修改」怎么走

1. 前端 `App.vue › runAgent` 发 `POST /api/projects/{id}/agent/stream`，带上：这句话、点选的目标、预览现场（停在哪页、点过什么、报错）、界面语言。
2. `agent.py › _run_agent` 组背景资料（页面骨架、修改意见、定位目标），一轮轮调模型；模型只能调工具，不直接回整页 HTML。
3. 工具（`TOOL_SPECS`）：读页面 `inspect_page / search_source / read_source_slice / read_region`，改页面 `apply_operations / start_from_shell`，
   计划 `update_plan`，收尾 `report_result / ask_user / answer_user`，另有组件、skill、记忆、查历史对话等。
4. `apply_operations` 交给 `patcher.py`：按原始源码区间替换，没碰到的源码一字不改；改完跑静态检查（结构、脚本语法 `node --check`、外壳页面的禁用写法）。
5. 循环结束得到候选，`transactions.py` 暂存；前端用 `bridge` 在隐藏 iframe 里跑启动检查，通过才 `commit` 成新版本；不通过保留上一版，失败的那份存进 `runs/failed-*` 供「让 AI 修复」。
6. 改动较大时，前端 `lib/probe.js › selfTest` 让 bridge 把每页按钮点一遍；有问题自动带着问题清单再跑一轮修复。
7. 每次运行的轮次、工具、token 记在 `data/projects/<pid>/runs/*.json`，排查「为什么绕了这么多轮」看这里。

## 目录

| 位置 | 是什么 |
|---|---|
| `backend/server.py` | 建应用：只收本机同源请求、统一错误处理、挂上各领域接口、托管界面文件 |
| `backend/routes/` | 接口按领域分文件：`settings` 配置与规范和组件、`memory` 记忆、`projects` 项目与回收站和风格、`pages` 页面与版本和预览、`agent_runs` AI 运行 |
| `backend/agent.py` | AI 主循环：拼提示词、每轮调模型、执行改页面的工具、计划自动推进、空转守卫和收尾 |
| `backend/agent_tools.py` / `agent_source.py` / `agent_context.py` / `agent_lookup.py` | 工具清单；读源码（分段读、搜索、定位行号）；拼背景（弹窗位置、预览现场、语言、外壳）；查资料工具（skill、组件、对话、记忆） |
| `backend/patcher.py` | 补丁操作、样式白名单、外壳写入 `shell_add`、静态检查 `verify_source` |
| `backend/bridge.py` | 注入预览的脚本（以字符串存着的 JS）：点选、悬停、图层、属性读取、自检 `selfTest` |
| `backend/transactions.py` / `storage.py` / `atomicio.py` | 两阶段提交、磁盘存储（原子写）、版本与撤销 |
| `backend/memory.py` / `conversation.py` | 项目记忆、个人习惯、对话检索 |
| `backend/skills.py` / `skill_digest.py` / `components.py` | skill 包、风格（每个项目选一套）、组件库 |
| `prompts/styles/` | 软件自带的风格，分后台 / 中台 / 手机三类各三套，由 `scripts/生成内置风格.py` 生成 |
| `backend/paths.py` | 程序自带文件（只读）和用户数据的位置；桌面版用户数据在系统的应用数据目录 |
| `prompts/` | 系统提示词（agent / discussion）、默认设计规范 |
| `frontend/src/App.vue` | 共享状态和基础动作（请求、刷新、换项目、快捷键），把各块拼起来 provide 给界面组件 |
| `frontend/src/composables/` | 按功能拆开的逻辑：AI 运行、检查提交、弹窗与风格、预览消息、展开、截图、导出、画笔、演示。互相调用写 `s.xxx`（调用时才取） |
| `frontend/src/components/` | `layout/` 顶栏、对话、属性面板、弹窗；`chat/` 执行卡片、结果卡片；`expand/` 展开图；`settings/` 模型、记忆、文件 |
| `frontend/src/lib/` | 不依赖界面的逻辑：流式解析、预览文档、展开存储与导出、自检、`i18n.js`、`desktop.js` |
| `frontend/src/locales/en.js` | 英文翻译表（键是中文原文） |
| `desktop/` | 桌面外壳 `app.py`、PyInstaller 配置、Windows 安装程序、发布前检查、GitHub Actions 配置 |
| `scripts/` | 双击用的脚本；`serve_fixture.py` 模拟模型的隔离验收服务；`bench/` 一键生成对比测试 |
| `sample/starter.html` | 新建项目的空白模板 |
| `data/` | 源码运行时的本机数据（不进版本库） |

## 约定

- **文案**：界面直接写中文，模板里 `$t('中文')`、脚本里 `t('中文')`；英文补在 `locales/en.js`。`frontend/tests/i18n.test.js` 会查漏翻。
  后台拼好的整句（进度、报错）在前端按 `{0}` 模式匹配翻译，所以后台改了句子也要同步翻译表。
- **AI 只做局部修改**：不允许整页重写；`replace_region` 要先读过、精确补丁失败过才放行。
- **用户数据和程序分开**：新的可写文件一律走 `backend/paths.py` 里的目录，不要往程序目录写。
- **安装包必须是空的**：别把 `data/`、`prompts/skills`、`prompts/components` 打进去，`desktop/release_check.py` 会拦。

## 风格

一套风格就是一个 skill 包（`SKILL.md` + `assets/页面外壳.html`）。每个项目在 `project.json` 里记 `style`：
`builtin:简洁后台`（软件自带，只读）/ `mine:文件夹名`（自己导入的）/ `none`（不选，只按设计规范）。
没有这个字段的是以前建的项目，照旧用装了的全部 skill。AI 只看这个项目选的那一套，几套之间不会打架。

- 新建原型时选了带外壳的风格，第一页直接就是那套外壳；AI 第一次修改时直接 `shell_add` 往里写，不用先读源码。
- 导入的原型默认 `none`，保持原样。
- 内置风格 = 共用骨架 + 皮肤（CSS 变量）+ 布局（左侧菜单 / 中台顶栏 + 二级菜单 / 大屏 / 手机）+ 写法说明。
  说明按 DESIGN.md 的思路写（用途、视觉基调、配色怎么用、布局、要做和不要做），通用部分带一份「一眼像 AI 做的」禁用清单。改它们改 `scripts/生成内置风格.py` 再跑一遍，
  `backend/tests/test_styles.py` 会检查生成结果和仓库里的一致。

## 测试

```bash
python3 -m unittest discover -s backend/tests -t .   # 后端，约 200 条
cd frontend && npm test                              # 前端，约 66 条
python3 scripts/serve_fixture.py                     # 不联网的手动验收（模拟模型）
python3 scripts/bench/check.py <页面.html> <输出目录>  # 一键生成的页面自动点检，见 scripts/bench/README.md
```

## 后续优化清单（按收益排）

1. **生成效率**：一张复杂页面要 15–20 轮、约 50 万 token。先看 `runs/*.json` 找重复读取和来回试错，减少每轮重发的上下文。
2. **拆大文件**：`App.vue` 已拆（逻辑在 `composables/`）；`server.py`、`agent.py` 已拆；还剩 `bridge.py` 里的 JS 挪成单独的 `.js` 文件，能被 node 直接测。
3. **密钥进系统钥匙串**：现在明文存在 `data/config.json`。
4. **设置里加「清除所有数据」**，以及打包缓存清理。
5. **英文覆盖**：后台少数进度和报错没进翻译表；给 AI 的内部指令是中文的（已靠界面语言提示兜住）。
6. **发布**：Mac 签名公证、Intel 版；Windows 代码签名。
